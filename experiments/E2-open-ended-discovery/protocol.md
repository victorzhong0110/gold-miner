# E2 无目标发现：同等翻译条件下的探索实验

日期：2026-09-17。状态：方案草案，尚未运行。
对应 [v0.4 的 W5/W9](../../docs/plan/v0.4.md)；自然度的完整验证仍属于后续 E4。

## 1 核心问题

用户没有明确搜索任务时，额外推荐能否带来此前不知道、值得使用、学习或继续探索的项目？把两边的阅读条件拉齐后，收益是否仍存在？

不以点击率、停留时长、推荐数量或 Star 数量单独宣告成功。项目探索可以是兴趣驱动，不强制每次都安装软件才算有价值。

## 2 E2a：人工辅助候选，先判断值不值得看

### 对照条件

- A：用户照常浏览 GitHub，可使用固定设置的现成翻译工具。
- B：同样的浏览与翻译条件，额外提供少量相关但有差异的候选。首轮可人工获取和核对，以简单列表或实验卡片呈现。
- 翻译工具、目标语言、可用阅读帮助和单次时间上限一致。B 的人工准备时间单独记录，不能当成未来自动系统的速度或成本。
- 不建设独立发现网站。实验材料只用于候选价值探索，不冒充扩展产品或原页无感体验。

### 会话建议

发起人先完成两对短会话，单次约 10–15 分钟；一对 A 后 B，另一对 B 后 A。使用不同但兴趣相近的起点，降低顺序与已见内容影响。数量与时长在实际开始前记录，不构成统计显著性设计。

让用户选择“今天愿意逛哪类东西”，不要求先编写具体需求。记录工具、冷门问题、学习实现等探索意图；不要让所有会话都围绕一个技术类别。

在需要阅读时允许正常翻译。若工具失效或质量明显不同，记录该段比较受影响，不将改善归因于推荐。

### 候选获取

依据当次兴趣和当前项目，从可核查的公开来源新取候选，保存查询与来源。可以参考社区清单、主题页或实时搜索，但不能只从此前 22 个演示仓库挑答案。

每次最多呈现约 3 个候选，先用统一简短格式：用途、与当前兴趣的关系、已知条件、原文依据。未知条件如实写未知；不靠夸大宣传吸引点击。

记录候选在呈现前是否为用户所知；无法预先询问而不造成剧透时，浏览后询问并标明回忆判断。所有展示和被略过候选都记录，不只保留成功项。

### 能得出的结论

E2a 可以说明某种候选及理由是否吸引人，帮助选择自动推荐输入。它不能证明自动获取、在线排序、等待时间、首次配置或页面导航体验有效，也不是未来效果的保证。

## 3 E2b：自动方法是否保留价值

E2a 出现具体有用案例后，再用可记录的简单方法从真实来源获取候选。先用用途、用户选定兴趣和当前仓库上下文，不依赖其他用户的行为数据。

拆开两项检查：

1. 同一个新获取的候选池、相同显示格式下，比较简单非个性化排序与按兴趣/上下文排序。它只判断排序作用。
2. 使用新的浏览起点，从开放来源重新获取候选，再与正常浏览比较。它检查获取与推荐的整体可用性，不受固定池限制。

首次排序与后续反馈调整分开记录。先冻结简单规则和探索比例；“不感兴趣”是明确反馈，“没点”保留为未知。展示少量不同方向，允许关闭或减少某类内容，不自动生成无限信息流。

如要比较联网 AI，让它在相同的简短兴趣与当前项目背景下给出项目，不给它事后知道的具体目标；记录工具、人工提示次数和耗时。不能用明确任务搜索代替无目标发现对照。

## 4 记录与价值判定

每条会话至少记录：

- session_id、参与者代号、阅读语言、条件 A/B、翻译工具及设置、起点、兴趣、开始/结束、顺序。
- 候选仓库、来源/查询、方法与版本、排序、实际展示、用户是否原本知道。
- 是否打开、是否值得继续、具体理由、期待的用途或学习点、已知条件与未知项。
- 干扰、困惑、等待、重复推荐、返回困难，以及“暂时没需要”等放弃原因。
- 人工准备/核对时间、搜索次数、模型调用和可见费用；缺项标未知。

首要结果是带理由的有价值新发现，以及用户是否认为这段探索值得。辅助记录点击、收藏、停留和发现时间；不把快速离开一律算失败。

参与者可在之后有机会时补充：继续阅读、尝试安装、学习实现、解决问题或没有后续行动。没有机会使用与试用后无用分开。该跟进只写进实验安排，本文件不创建提醒或自动消息。

## 5 偏差与语言边界

- 原则上让不同语言来源的候选获得相近的阅读条件；不能把外语导致的跳过直接解释成不感兴趣。
- 人工策展、研究者知道条件、发起人自测、起点差异与熟悉效应均须披露。
- A/B 用户看得见界面差异，不宣称体验盲测。后续独立候选判定可隐藏方法名。
- 发起人的中文体验不能替代英文使用者体验。英文方向可先准备材料与技术运行，体验结论等实际参与者。
- 对照中没有实际发生的行为不得由模型代填。用户原话、实施者观察和模型生成理由分列。

## 6 继续条件

- E2a 有具体新发现且理由可信：支持开展 E2b，不直接支持大规模扩展开发。
- E2b 在新起点有可复核收益，额外操作与费用可接受：支持最小扩展，再用 E4 测自然度。
- 个性化与简单排序相近：先保留简单方法；不为使用“推荐算法”而增加复杂度。
- 人工推荐有用而自动方法无效：记录差距，优先改候选或内容描述；不能隐藏人工劳动。
- 反复只有熟悉项目、空泛理由或被动点击：换一批材料核对一次；仍无具体价值时缩小或暂停推荐路径。
- E1 失败不自动终止 E2；E2 失败也不自动终止有价值的主动搜索。

## 7 与 E4 的衔接

最小扩展阶段从安装开始观察：首次展示、首次需要 API 配置、是否需要 GitHub 凭据、等待、失败、关闭、继续浏览与返回。不要求先完成配置才入组。

记录“先看已有资料，再配置”和“直接配置”的实际差异；自备 API 和零公共补贴保持不变。自然度必须通过真实页面操作验证，不能从手工候选实验外推。
