## 任务与验收

| ID | 任务 | 执行内容 | 验收标准 |
|---|---|---|---|
| WP4-01 | 开放候选来源 | 组合当前项目相关源、用户兴趣、双语扩展，记录每路来源与原始排名。 | 共享条目不是唯一来源或白名单；区分项目工具、学习实现和资料集合。 |
| WP4-02 | 规则排序与多样性 | 比较简单排序、规则重排；去重、已见过滤、主题/作者集中控制、低 stars 项目保留。 | 实际验证探索余量生效；不把头尾拼回原序列当成多样性实现。 |
| WP4-03 | E2b 自动推荐验证 | 先在同候选池比排序，再在开放来源中新取候选比较获取能力。 | 人工筛选、自动排序和自动获取的贡献分别报告；新起点复测。 |
| WP4-04 | 轻量个性化 | 兴趣和当前页面默认；历史/stars额外选择启用；反馈、重置及关闭生效。 | 缓存展示前按最新反馈重排；看不懂造成的跳过不直接认作不感兴趣；点击/停留不作主要效果指标。 |
| WP4-05 | 缓存与模型模式切换 | 设计内容版本、语言、处理方式和配置变化失效策略；区分原始候选与展示结果。 | 含未结 R1：旧 rules 缓存不能阻止已配置模型首次尝试或恢复；版本不能仅凭不变页面标题代表 README 更新。 |
| WP4-06 | 预算、取消和并发 | 请求去重、次数/长度/并发上限、限流退避、取消与重试边界、缓存命中计量。 | 取消/失败不计成功；已发出调用可能计费；不自动充值、换账户或公共补贴。 |
| WP4-07 | 成本等待报告 | 实际测完整使用过程、失败路径、首次配置与二次访问的费用和等待。 | 模型/GitHub分别计量；未知 tokens 或费用记未知，模拟耗时不充当真实延迟。 |

## 交付与范围边界

Alpha 版本、候选与重排记录、E2b 对照、预算/缓存/取消回归证据、费用与等待报告。

能获得可解释候选、反馈和开关实际生效，成本符合个人 BYOK 边界；没有价值证据时收缩规则与范围，不训练大型推荐模型。

实施者在实际任务授权中声明拟改路径，优先复用对应 experiments/、extension/、scripts/ 与 docs/ 下已有材料；本计划不要求为路径占位创建空文件。尚未合并的路径必须注明所在 PR/head，不能当 main 文件引用。

## 验证与交接

执行前从[状态表](STATUS.md)登记唯一写入者、实际工作区与基线 SHA。每个子任务分别回报实现、验证、提交、合并、实际验收，附命令、结果、对应 SHA、证据路径和未运行理由。只运行能解决当前风险的测试；个人凭据与真人反馈缺失时保持待验证。

实际验收通过后由评审方确认本包出口；合并由用户授权。暂停或换执行者时保留工作区，不 reset/clean/stash，不在其他窗口重复派发同一任务。
