# 0002 模型接入与首次配置

更新：2026-09-17。
状态：v0.4 采用的实现方向；尚未编写适配器或进行个人模型请求。

## 原则

使用者自备 API，服务可替换；发起人的中国站 MiniMax Token Plan Starter 是首个个人试用资源。先验证实际账户可用的端点、模型、协议和调用范围，不从套餐名称推断效果、额度或无限使用能力。

首轮只实现实际验证过的协议；预留其他服务的接入边界，不承诺全部 OpenAI/Anthropic 兼容端点都能直接工作，也不要求发起人逐个选择框架或供应商。

## 配置

配置包含服务预设、协议、地址、模型和个人密钥。常用预设减少填写，地址与模型等高级项可展开。仅在预设确实提供用量查询时显示供应商余额；未知时显示未知，并展示本地可确定的请求统计。

首次使用可先看已有公开资料或不需新模型调用的结果，实际需要生成时再引导配置。其效果属于 E4/E6 的待验证设计，不是已经实现的无配置能力。GitHub 凭据与模型密钥分别处理，仅在实际需要时引入前者。

## 最小连接探测

在使用者本地配置密钥后，以一小段公开文本发最小请求，记录请求模型、可见返回标识、格式、延迟、用量与错误。模型与套餐适用范围在执行时以官方资料和实际账户为准。失败应区分地址、协议、权限/凭据、额度、网络与响应格式。

不用发起人的账号为公众提供额度，不提供公共推理代理，不自动充值、升级或切换按量账户。每次请求需受预算、有限重试、输出限制与取消控制；已发送请求可能已消耗额度。

## 密钥与数据边界

后台发出模型请求，页面内容脚本只获得任务结果。密钥不进入 sync、页面 DOM、日志、共享条目或导出。

持久保存为使用者可选；若用 chrome.storage.local，必须限制为受信扩展上下文，不能把“存在 local”视为已隔离内容脚本。设置页与后台的访问、消息发送者与请求目标也要校验。参见 [Chrome storage 官方说明](https://developer.chrome.com/docs/extensions/reference/api/storage)与[工程检查](../engineering/prerequisites.md)。

公开 README 等第三方内容按数据处理，不能因其文本包含“指令”而改变凭据、请求目的地或工作范围。

## 后续选项

本地模型与其他供应商可在已有路径不足或有人需要时增加。本地推理可能避免外部 API 费用，但仍有硬件、资源和配置成本；本计划不把它称为无成本保证。
