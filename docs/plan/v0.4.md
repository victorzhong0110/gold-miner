## 1 目标与约束

黄金矿工让用户用自己的语言发现、阅读、继续探索 GitHub 项目。首要场景是没有明确目标的浏览，同时支持中英双向主动搜索。

已确认约束：

- 工作名沿用黄金矿工 / Gold Miner；首个产品载体为 GitHub 原页面中的 Chrome 扩展。
- 默认推荐，用户可自行选兴趣；覆盖小工具、冷门问题方案、学习型实现。
- 首轮中英文双向；技术验证和相应语言使用者体验分别报告。
- 忠实阅读、可查看原文；解释性教学与代发 issue 后置。
- 零公共模型补贴，使用者自备 API；发起人的现有 MiniMax 套餐只作个人试用资源。
- 公开候选来自真实可核对的来源，不被共享译文库或预选列表限定。
- 翻译按需，尽量复用；共享从小规模可交换内容开始。
- 开源、短期非盈利；先自己试用，后续才考虑推广。
- 个性化先用兴趣与当前项目；stars、浏览历史和贡献数据需用户选择启用，偏好优先本地保存。
- 黄金矿工本身也需要能通过中英文名称与功能词被搜索找到。

具体框架、数据结构、去重、错误恢复、实验记录格式由实施者确定，不逐项交给发起人选择。

## 2 本轮改变了什么

1. 将足够好的翻译放进对照组，检验额外发现收益。
2. E1 搜索与 E2 无目标发现分别判断；两条研究路径可独立推进，执行时仍可一次完成一个工作包。
3. 不以中文 README 占比决定某一语言方向是否值得做；大规模 H0 抽样后置。
4. E1 增加同语言、同预算对照，避免将更多查询或不同字段带来的收益归因于跨语言。
5. 学习型项目纳入有效发现，命中率不冒充总体召回。
6. E2 先做轻量候选实验，只有自动候选具备价值后才扩大扩展开发。
7. E4/E6 从安装与配置开始；不默认要求 API key 和 GitHub 凭据全部配置完才体验。
8. 共享探索增加“项目发现条目”，但不建设全量项目数据库。
9. 名称保持，先改进双语用途信息再复测。许可证、供应商名单等独立事项不阻塞无关实验。

| E7 持续使用 | 现在准备轻量日记模板 | 后续区分看过、收藏、实际试用、学习、再回来；无使用机会单列 |

| E9 词表/AI/混合 | 先复用 E1 任务；仅在需要解释增益时展开 | 固定候选预算与检索字段，纯词表组不得暗中调用模型 |

E3 首轮可用少量公开片段，覆盖两方向和主要格式；片段数量在运行前固定。E5 先做本地跨环境复用，真实公共托管免费额度另行核对。技术双向运行与语言使用者体验是不同证据。

## 6 最小数据、推荐与工程边界

### 发现条目

最少保存：规范仓库地址、中文/英文用途、检索别名、类型、能力与条件、原文链接/定位、来源版本、读取时间、机器生成或人工确认状态、未知项。长篇译文另外按需缓存。

共享条目不能成为推荐白名单，不能声称会自动改变 GitHub 原生索引。用户私有信息与贡献内容分开；贡献默认关闭。

### 推荐与反馈

先以兴趣、当前仓库和明确反馈做简单排序；每次少量候选并保留多样性。点击、停留、Star 均为辅助信号。“有价值的新发现”要求用户原本不知道且能说明用途、学习点或继续探索理由。学习项目按学习目标评价，不套用开箱即用标准。

对照组与增强组使用同样的翻译条件。文档语言是内容来源特征，展示语言是用户设置；不能将看不懂造成的跳过直接学习成不感兴趣。

### 模型、凭据与成本

MiniMax 是个人首个试用资源，供应商可替换。服务预设与高级配置分开，首轮只实现实际验证过的协议；不承诺任何兼容服务都能直接工作。端点、模型、套餐适用范围和实际用量在连接时核对。

没有模型配置时，可以先看已有公开材料与不需新调用的结果；具体覆盖受实测限制。GitHub 凭据按实际需要引入。模型不经过公共代理，密钥不进入网页、日志、导出或共享包；内容脚本与密钥存储访问边界必须实测。

请求设置次数、长度、并发、重试和取消边界。未知余额显示未知；不自动充值、升级、切换按量账户。已发送请求可能已经产生费用。小实验可以只用公开读操作，付费部分没有本地配置时单独标为待运行。

具体实现前读[工程检查](../engineering/prerequisites.md)；只执行与当前工作包相关的检查，不把全部未来功能变成开工门槛。

## 7 首轮评价与分支

| 观察到的结果 | 下一步 |
|---|---|
| 简单译词与复杂跨语言方案相近 | 保留简单方案；E9 仅用于找出必要的术语或语境能力 |
| 跨语言方案优于一次搜索，但不优于同语言同预算扩展 | 不宣称跨语言独有收益；检查一般查询扩展是否已经够用 |
| E1 有实际增益，E2 无明显收益或持续打扰 | 先做搜索入口和阅读连续性 |
| E2a 有具体价值，自动候选尚不稳定 | 优先 W9，不提前宣称自动推荐有效 |
| 自动 E2 有增益，复杂 E1 无增益 | 推进发现体验，主动搜索保留最简单可靠路径 |
| 现成翻译足够 | 使用它作为阅读基础，减少自建翻译与长篇缓存投入 |
| 强对照在发现、负担和成本上同样好 | 缩小为补充功能或暂停独立产品；保留失败记录 |
| 只有开发题或人工固定池表现好 | 换一批未用于开发的任务/开放来源复查；不扩大开发 |
| 用户难以完成自备 API 或费用不可接受 | 减少调用与配置负担，复测；不以公共补贴掩盖问题 |
| 搜索与自动发现都没有可复核增益 | 检查一次可解释的失败原因后决定暂停，不无限追加功能 |

不在首轮用任意百分比或少量点击宣布普遍有效。报告至少保留：所有任务与失败、双方独有的好项目、用户原话、来源、请求量、时间、判断者身份及未观察到的内容。小样本存在熟悉效应、选择偏差与非盲判断时直接写明。

## 9 暂缓清单

独立发现网站、全量 GitHub 爬取与自建搜索基础设施、大型推荐模型训练、公共推理代理、整仓库预翻译、实时多人纠错平台、issue 自动发布与代码修改、初学者教学模式、多于中英文的全面支持、商店上架和付费运营。

功能、示例、讨论级发现值得保留，但首轮先验证仓库与 README 的发现价值。历史演示的 22 个仓库和 20 道开发题不作为开放检索证据；若后续归档，只标明为演示材料。
