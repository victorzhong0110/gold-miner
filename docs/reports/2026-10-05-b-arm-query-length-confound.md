# 2026-10-05：B 组的查询长度会让 B→C 比较失真

起因是复核 B 组那次 HTTP 422。`runs/2026-10-04-bcm-minimax/report.md` 已注意到
「B 组长句整句直译可能超出 GitHub 搜索接受范围（本次 1 条 HTTP 422）」。
本轮把它量化，结果比「一次不幸」严重得多。

## 1. B 的查询长度是结构性偏长，不是巧合

`2026-10-04-bcm-minimax` 里各组生成查询的字符长度：

| 组 | 条数 | 最长 | p90 |
|---|---|---|---|
| **B** | 20 | **193** | 103 |
| C | 76 | 53 | 38 |
| M | 60 | 75 | 59 |

B 的最长查询是 C 上限的 **3.6 倍**、M 的 2.6 倍。原因是设计使然：
B 组定义为「原文 + 一条**忠实整句**翻译」，而 C/M 的提示词要求
「最多 2–3 条**同义用途词**」。所以 B 天然产出整句，C/M 天然产出关键词。

## 2. 实测：GitHub 对长查询不只是报错，是几乎检索不到

用 B 组实际失败的那条查询（`zh2en-eval-10`，193 字符）逐步截断到词边界，
未认证请求 GitHub 公开 `search/repositories`：

| 长度 | HTTP | total_count |
|---|---|---|
| **193**（实跑失败的那条） | **422** | — |
| 141 | 200 | **0** |
| 86 | 200 | 1 |
| 65 | 200 | 1 |
| 36 | 200 | 47 |
| 22（同批对照） | 200 | 151 |

机器可读记录：
[`query-length-probe-2026-10-05.json`](../experiments/E1-cross-language-search/query-length-probe-2026-10-05.json)

**422 可复现**（与 2026-10-04 实跑记录一致）。但更关键的是第二层：
65–141 字符区间**不报错，却几乎检索不到东西**（0–1 条），
而 22–36 字符区间是 47–151 条。

也就是说 B 组的问题不是「偶尔踩雷」，而是**它的查询形态与 GitHub 关键词检索
结构性不匹配**：不报错的时候，结果也基本等于零。

## 3. 这会污染协议第 6 节的 B→C

协议第 6 节：「**B→C 判断复杂程度是否值得**」。

如果直接读 C−B 的数字，会以为它衡量的是「跨语言扩展 vs 忠实翻译」的质量差。
但按上面的测量，它**同时在衡量「关键词长度 vs 整句长度」**——
而后者与翻译质量无关，只与检索系统的形态有关。

具体地说：C 拿 47–151 条候选去比 B 的 0–1 条，这个差值的很大一部分来自
**B 的提示词产出整句**，而不是来自「C 做得更好」。

于是可能出现这种误读：看到 C 远好于 B，得出「跨语言扩展值得这个复杂度」，
而真实原因之一是 **B 这一臂被实现成了一个稻草人**。

**这不是说 B 该从协议里删掉。** B 作为「只做简单翻译」的对照仍然有意义。
问题在于它当前的实现方式让对照失真：B 应当检验
「把原话**当关键词**翻到另一语言」与「跨语言扩展」的差别，
而不是「把原话当整句翻过去」——后者测的是 GitHub 喜不喜欢长查询。

## 4. 本轮不修

B 的提示词是冻结材料，协议规定修复落 `eval.batch_2`。而且这不是纯技术修补，
是**实验设计取舍**，属发起人决定：

- 让 B 产出关键词长度查询（与 C/M 同长度量级），则 B→C 隔离出「语言」这一个变量
- 保持 B 现状，则 B→C 必须标注为「关键词 vs 整句」的混合差值，不能当翻译质量读

两条路都可辩护，取决于想回答哪个问题。**本轮只把测量做出来并记录，不代做选择。**

## 6. 验证与边界

- 1 条查询、6 次请求，间隔 7 秒，**不足以给出精确长度阈值**
- 未认证（公开配额）；认证后行为可能不同
- `total_count` 随 GitHub 索引变化，不是稳定量；此处只用来说明**量级差异**
- 全程付费模型请求 0；未改动任何提示词、材料或既有运行记录
- `python3 scripts/run_offline_suite.py` exit 0：**347 Python + 58 Node**（未新增测试；
  本记录为一次性测量，未引入代码）

**本记录不构成 E1/E2/E3 任何效果证据**，也不改变已完成运行的任何结论。
它只说明：B→C 这个数字含有一个已测量的混淆因素。
