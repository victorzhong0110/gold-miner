# 2026-10-05：B 组查询长度 —— 一条自我推翻的记录

> **本记录已被自己推翻。** 保留在此是因为它记录了一次完整的
> 「测量 → 过度外推 → 被数据否证」过程，以及否证它的数据。
> 最终成立的结论只有一条，见第 5 节。**请不要引用第 2–4 节的任何推断。**

起因是复核 B 组那次 HTTP 422。初版报告称 B 组查询「与 GitHub 关键词检索
结构性不匹配」「被实现成了稻草人」。**那两条都不成立。** 下面是过程与数据。

## 1. 初版做了什么

`runs/2026-10-04-bcm-minimax/report.md` 注意到「B 组长句整句直译可能超出
GitHub 搜索接受范围（本次 1 条 HTTP 422）」。我据此测了 6 次请求
（机器可读记录见 `query-length-probe-2026-10-05.json`），看到：

| 截断长度 | HTTP | total_count |
|---|---|---|
| 193（实跑失败那条） | 422 | — |
| 141 / 86 / 65 | 200 | 0 / 1 / 1 |
| 36 / 22 | 200 | 47 / 151 |

然后写成：B 的问题不是偶尔 422，而是**查询形态与 GitHub 关键词检索结构性不匹配**，
C−B 因此被污染，**B 这一臂被实现成了稻草人**。

## 2. 错在哪：我的探针同时改变了两个变量

那条 193 字符的查询是**一句完整的话**。我把它按词边界截断到 141 / 86 / 65 字符，
得到的**不再是同一句话的缩短版，而是语义破碎的片段**。

所以 141 字符返回 0 条，测到的不是「长查询检索不到」，
而是「这句被截断的半截话检索不到」。**长度和语义完整性被我绑在了一起**，
这是单变量原则的违反。36 和 22 字符那两行之所以有 47 和 151 条，
是因为截断点恰好还落在一段语义完整的短查询上——它们跟 141 那一行不是同一个实验。

## 3. 实跑数据否证了「稻草人」结论

回到 `2026-10-04-bcm-minimax` 本身，把 B 按「原查询结果」和「译句查询结果」拆开：

| 组 | per-query 记录 | 其中来自原查询 | 其中来自生成查询 | 跨题去重仓库 | 合并候选 |
|---|---|---|---|---|---|
| A | 70 | 70 | 0 | 51 | 70 |
| **B** | 242 | 70 | **172** | **156** | 212 |

集合关系（跨题去重）：

```
B − A = 106      A − B = 1
C − A = 247      C − B = 202      C − M = 225
```

**B 贡献了 156 个去重仓库，比 A 的 51 个多一倍，其中 106 个是 A 没有的。**
如果 B 是稻草人，不可能有这个数。初版报告那句「B 这一臂被实现成了稻草人」
**与数据相反，已撤回**。

## 4. 逐题看「译句查询长度 → 返回条数」，长度不是干净的解释变量

| 译句长度 | 20 题的返回条数 |
|---|---|
| 9–21 字符（8 题） | 13, 0, 10, 0, 25, 21, 0, 0 |
| 22–48 字符（10 题） | 30, 14, 0, 0, 30, 18, 1, 3, 7, 0 |
| 103 字符 | 0 |
| 193 字符 | 0（该题 `partial`，422） |

**20 题里 11 题的译句查询返回了 ≥1 条**。而返回 0 的 9 题里，
有 4 题长度只有 13–21 字符——短查询同样检索不到。

所以「B 译句查询 9/20 返回空」是事实，但**在本批数据上无法归因于长度**：
短查询照样有 4 题是空的。冷门用途的忠实译句本来就可能没有匹配，这与长度无关。
把 9/20 归因于「长查询失效」是我在证据不足时的过度解读。

## 5. 最终成立的结论

只有一条：

> **`zh2en-eval-10` 那条 193 字符的 B 译句查询，可复现地返回 HTTP 422。**
> 这是 20 题中的 1 题，表现为该题 `status=partial`。
> 除此之外，没有证据表明 B 组查询存在系统性的长度劣势。

以及一条仍然有价值的观察，但**不是缺陷**：

> B 组的译句查询在 20 题中有 9 题返回 0 条，短查询同样会返回 0 条。
> 这更可能是「忠实整句直译的检索命中率本来就低」，
> 而不是某处坏了。若要判断 B 的直译策略是否合适，
> 需要的是人工判定（已在 [2026-10-05-analysis-missing-b-comparison.md](2026-10-05-analysis-missing-b-comparison.md)
> 的准备范围内），不是长度推断。

**撤回**的三条：① 长度导致结构性检索失败；② C−B 被长度污染；③ B 是稻草人。

保留的一条：193 字符查询可复现 422（1/20 题）。

## 6. 为什么仍然保留这份记录

初版报告和 STATUS 都写了上述三条错误推断，PR 评论也发了。
把它们留在仓库里并标记为已推翻，比悄悄改掉更有用：
下次有人想用「B 组查询太长」解释任何 C−B 数字时，
会先撞见这份「我们试过，被数据否了」。

同时这也是一次可复用的教训：
**当探针本身改变了被测对象（截断一句话 = 改变它的语义），
测出来的差异不能归因于你在操纵的那个变量。**
单条查询的 6 次截断，不足以支撑关于检索系统的任何一般结论。
