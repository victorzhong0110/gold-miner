# 工程检查：按工作包执行

更新：2026-09-17。当前执行顺序见 [v0.4](../plan/v0.4.md)。
本文区分官方接口约束、设计要求与待实测项；没有代表已经验证的运行记录。脚本阶段只需完成相关来源与请求检查，不要求先完成整套扩展工程。

## 1 W2/W3：候选获取、配额与可追溯性

- 对公开来源先验证无凭据路径，记录接口、字段、返回窗口、失败和可见限流头。搜索与内容获取预算分别计数；配额依据实际认证方式、端点和响应确定。
- 同语言与跨语言比较使用相同字段、预算和排序；README 搜索另做配对检查，详见 [E1](../../experiments/E1-cross-language-search/protocol.md)。
- 缓存重复请求、串行或有限并发、按限流响应退避；不能用固定两秒间隔保证不会限流。
- 有必要时再引入用户自己的最小权限 GitHub 凭据；没有凭据时显示真实可用范围，不预设一定够用或一定不能用。
- 规范仓库地址并保存候选来源；仓库存在性、迁移、镜像和类型分别核对。模型生成的仓库名不能直接当来源。
- 查询和 README 的语言行为通过小样本诊断，不从命中少量短语推断全站覆盖。

依据：[GitHub REST 限流](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)与[请求最佳实践](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。实现时核对当前接口文档，不把旧额度写成所有用户的保证。

完成记录：保存实际请求配置、计数、错误、来源和未检查项。

## 2 W6/W10：模型适配与费用

模型服务、协议、地址、模型、密钥分开配置，首轮仅支持实际测过的路径。详见 [0002](../decisions/0002-model-endpoint-config.md)。

要求：小请求连接探测；有限请求数、输出长度、并发与重试；合并重复任务；取消后停止新任务；保留已发送请求可能已计费的状态。套餐余额无法确定时显示未知，不自动充值或切换账户。

公开内容发往使用者所配服务时，按已说明的模型处理范围执行。仓库文本、README 或返回结果不能指挥系统改变端点、请求私有资源或暴露密钥。

完成记录：实际响应格式、等待、请求统计、失败类别和恢复结果。密钥不进入记录。

## 3 W10/W11：GitHub 原页面交互

检查页面初载、站内导航、README 更新、返回与前进；只使用实测有效的定位与事件。避免重复注入；找不到锚点时停止对应功能并保留可诊断状态，不破坏 GitHub 页面。

界面只显示少量候选，理由与原文可追溯，可关闭和返回。样式隔离方式由实现选择，需确认不影响原页面操作。用户先看见内容、再配置模型的流程也要在真实页面测，不只看静态卡片。

完整 issue/注释翻译后置到实际阅读需要；第一段 README 与候选流程不等待全部页面类型支持。

## 4 W10/W11：MV3、存储与密钥隔离

- 页面内容脚本处理展示与有限公开上下文；后台处理模型请求和预算。设置页是受信扩展界面，页面不得得到密钥。
- 密钥持久保存由用户选择；不用浏览器 sync。若采用 chrome.storage.local，调用访问级别设置使其仅向受信上下文开放，并实际测试内容脚本无法读取密钥。
- 消息处理校验发送者、允许的任务和配置好的请求目标，不能暴露接受任意 URL 的带凭据代理。
- 权限只申请当前功能需要的范围；模型域名按配置申请。先测缓存配额与淘汰，不预先要求 unlimitedStorage。
- service worker 可能被终止，任务状态不能只放内存；恢复、取消和预算需要一致。持久状态不能消除“请求已发送但响应未落盘”的不确定性，这类任务应标未知，不自动重发造成重复费用。
- 日志与导出采用字段白名单，并对已配置密钥及认证头做兜底扫描；不能只查某种 sk- 前缀。
- 机密配置、偏好/历史、公开资料和可共享包分别处理。推荐默认开不等于历史上传默认开。

官方说明：Chrome storage.local 默认可被内容脚本访问，可通过访问级别调整，见 [storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。后台生命周期见 [service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。这些说明不代替实际隔离与恢复验证。

## 5 W12：原文获取、版本与复用

已打开页面中的文本必须确认是原文，避免将其他翻译工具改写后的 DOM 当作作者内容。无法确认时从可定位的原始来源读取，保存来源版本或内容校验值。

GitHub README 接口的 raw 响应是原文；需要 blob SHA 等字段时读取 JSON 元数据表示，不把 raw 文本当作带 sha 字段的 JSON。见 [README 接口](https://docs.github.com/en/rest/repos/contents#get-a-repository-readme)。

复用键至少区分仓库/原文位置、源文与相关上下文、目标语言和翻译配置版本。内容变化后只在依据仍一致时复用，不能仅凭相同段落文字忽略上下文变更。

条件 GET 可减少传输；“304 不扣主要配额”的官方说明有正确认证等条件，不推广为所有请求都免费。见 [条件请求说明](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api#use-conditional-requests-if-appropriate)。

导入包要检查格式、来源、版本和数据范围；未知或过期状态不能冒充已验证内容。没有共享包仍能获取新候选。

## 6 与实际风险对应的验证

| 工作包 | 必须核对的风险 | 证据 |
|---|---|---|
| W3 | 候选无来源、查询不配平、重复与错误被吞掉 | 小样本真实响应及结构化记录 |
| W6 | 配置错误、调用失控、费用不可见 | 最小连接、预算与失败记录 |
| W10/W11 | 导航重复注入、不能返回、密钥泄露、取消后继续安排调用 | 真实浏览与特定失败检查；必要时形成回归用例 |
| W10/W11 | 后台重启后无条件重发 | 中断恢复记录，不确定调用显式标记 |
| W12 | 原文变化后误用译文、导出个人数据 | 第二环境导入、源文变更和导出核对 |
| 自建翻译启用时 | 命令/标识符/链接受损，否定或限制被改变 | 原文定位与结构对比，严重误译单列 |

测试围绕已知风险和真实失败，避免为全部未来功能预先写大量镜像测试。通过工程检查只说明该路径可运行，发现效果与自然度仍分别由 E1/E2/E4 判断。
