# E8 多语言可发现性记录模板

对应 [v0.4](../../docs/plan/v0.4.md)的 W7/W14。复制为新日期的记录；同日多轮另加批次后缀，不覆盖已有探测。

## 条件

- 日期、时区、批次、操作者。
- 当时的仓库名、双语简介、topics、README 版本、许可证状态；是否刚改过这些字段。
- 入口分别列：GitHub REST API、GitHub 网页、普通搜索引擎；注明认证/登录、界面语言与可知地区。
- 查看窗口，例如前 20 条；没有检查的入口标“未检查”。
- 外部搜索记录是否已收录，不假设新仓库立即被收录。

## 查询

运行前固定中英文两类：名称加用途、纯用途。可以增加单独名称作为竞争诊断，但不要求裸名称排名第一。

| 入口 | 名称加用途示例 | 用途示例 |
|---|---|---|
| GitHub 站内 | 黄金矿工 跨语言；Gold Miner discovery | 跨语言 项目发现；cross-language project discovery |
| 普通搜索引擎 | 黄金矿工 GitHub；Gold Miner GitHub discovery | GitHub 跨语言搜索；GitHub project discovery across languages |

示例只用于准备，运行前还应加入实际用户的自然表达并记录来源。站内含 GitHub 的查询可以作为变体，但它是普通词项，不是“限定在 GitHub”的指令；不能把单一零结果查询当成市场空白证据。

## 每条结果

查询原文、语言、入口、时间、可见总数、前若干结果及官方仓库位置；未找到写“在本次窗口内未找到”。记录同名干扰、错误入口、限流和搜索失败，不能把接口错误记成零结果。

## 解读

- 名称加用途能否定位官方入口？
- 用户只知道用途时能否发现本项目？
- 相比上轮，改变的是名称、元数据、收录时间还是搜索入口？不能混为单一因果结论。
- 双语入口是否清楚？是否误以为已有可安装产品？
- 若仍明显混淆，是否需要副标题或其他名称方案？

完善元数据后的效果尚未知；首次探测只能说明当时的条件。改名不是实验的前置条件。

## 未检查与复现

列未检查入口、语言、地区及原因，保存真实步骤或命令和限流处理。用直接链接打开仓库、仓库内查找文本都不能代替外部可发现性验证。本模板没有产生任何新实验结果。
